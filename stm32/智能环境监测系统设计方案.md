# 智能环境监测系统设计方案

---

## 一、项目概述

### 1.1 项目目标

设计一套基于 STM32F103C8T6 + FreeRTOS 的智能环境监测系统，实时采集环境温湿度、光照强度、距离等信息，支持本地显示、离线存储、蓝牙透传，并为后续升级 ESP32 + MQTT 上云预留接口。

### 1.2 开发环境

| 项目 | 选型 |
|------|------|
| MCU | STM32F103C8T6 (Cortex-M3, 72MHz, 64KB Flash, 20KB SRAM) |
| RTOS | FreeRTOS |
| HAL 库 | STM32 HAL Driver |
| 代码生成 | STM32CubeMX |
| IDE / 编辑器 | VSCode + ARM GCC + Cortex-Debug |
| 后续升级 | ESP32-S3 + MQTT |

### 3.2 FreeRTOS 任务设计

| 任务名 | 优先级 | 栈大小 | DMA优化后 | 周期/触发 | 核心职责 |
|--------|--------|--------|-----------|-----------|----------|
| `vSensorTask` | 高 (4) | 192 words | ←256 | 事件驱动 (DMA通知) | ADC-DMA 取光敏值 / SHT20 / HC-SR04 |
| `vInputTask` | 高 (3) | 128 words | — | 50ms 周期 | 旋转编码器解码 + 按键消抖 |
| `vAnalysisTask` | 中 (3) | 256 words | — | 500ms 周期 | 阈值比较、报警判断、数据聚合 |
| `vDisplayTask` | 中 (2) | 256 words | — | 200ms 周期 | OLED 页面刷新、菜单渲染 |
| `vAlarmTask` | 中 (2) | 128 words | — | 事件驱动 | LED 闪烁控制、蜂鸣器 PWM 驱动 |
| `vStorageTask` | 低 (1) | 384 words | ←512 | 事件驱动 (DMA回调) | W25Q64 SPI-DMA 异步存储 |
| `vBluetoothTask` | 中 (2) | 256 words | — | 事件驱动 (DMA+IDLE) | USART-DMA 环形接收 / 协议解析 |
| `vMonitorTask` | 最低 (0) | 128 words | — | 10000ms 周期 | 系统心跳、CPU 占用率、栈水位 |

## 四、模块驱动设计

### 4.1 SHT20 驱动 (I2C1)

- 通信速率：100kHz (标准模式)
- 测量命令：温度 0xF3、湿度 0xF5
- 计算公式：见数据手册 §6.2
- 测量周期：主机模式，非阻塞，使用 `pdMS_TO_TICKS()` 等待

### 4.2 HC-SR04 驱动 (GPIO + 定时器)

- Trig 引脚：≥10µs 高脉冲触发
- Echo 引脚：输入捕获，测量高电平持续时间
- 距离公式：`距离(cm) = 高电平时间(µs) / 58`
- 使用 TIM2 CH1 输入捕获模式

### 4.3 光敏电阻驱动 (ADC + DMA)

- ADC1，通道 2 (PA2)，12 位分辨率
- 采样周期：239.5 个时钟周期
- 转换公式：`光照百分比 = (ADC值 / 4095) × 100%`
- **DMA1_CH1 循环模式**：64 次采样触发一次 DMA 半满/全满中断
- 中断频率降低 64 倍，CPU 采样期间完全解放
- 滑动窗口均值滤波：`fLight = AvgFilter(g_adc_dma_buf, 64) / 4095 × 100%`

### 4.4 OLED 驱动 (I2C2, SSD1306)

- 分辨率 128×64，页寻址模式
- 字库：6×8 与 8×16 ASCII，支持模拟中文
- 页面切换：主界面 / 详细数据 / 阈值设置 / 系统信息
- 使用 `u8g2` 或手写轻量驱动

### 4.5 EC11 旋转编码器

- A/B 相：外部中断 + 状态机解码
- KEY：消抖后触发事件 (单击 / 长按)
- 输出：旋转方向 + 步进值 → 放入消息队列

### 4.6 W25Q64 驱动 (SPI1)

- 容量：8MB (128 块 × 64KB/块)
- 最小擦除单位：4KB 扇区
- 存储格式：

```
+--------+--------+--------+-----+
| 时间戳  | 温度   | 湿度   | ... |
| 4字节   | 4字节  | 4字节  |     |
+--------+--------+--------+-----+
每条记录 = 20 字节，每分钟 1 条
日数据量 = 20 × 60 × 24 = 28.8KB
可存储约 284 天数据
```

### 4.7 蜂鸣器报警 (PWM)

- TIM1 CH1 (PA8)，频率 2kHz，占空比 50%
- 报警模式：急促短鸣 (连续超限)、间隔长鸣 (偶发超限)

### 4.8 蓝牙模块 (HC-05, USART1)

- 波特率 9600，主从一体
- 数据帧格式：

```
帧头    设备ID    温度     湿度     光照     距离    校验   帧尾
0xA5   1 字节   float   float   float   float   XOR   0x5A
共 20 字节
```

- 支持 AT 指令修改设备名、配对码

### 4.9 DMA 优化设计

STM32F103C8T6 内置 **DMA1（7 通道）**，可在 ADC、USART、SPI 传输中替代 CPU 完成数据搬运，显著降低中断频率和 CPU 占用率。

#### 4.9.1 DMA 通道分配

```
DMA1 通道映射 (无冲突，无需重映射):

CH1 → ADC1      ← 光敏电阻循环采样 (独占)
CH2 → SPI1_RX   ← W25Q64 读取
CH3 → SPI1_TX   ← W25Q64 写入
CH4 → USART1_TX ← 蓝牙发送
CH5 → USART1_RX ← 蓝牙接收
CH6 → 空闲
CH7 → 空闲
```

#### 4.9.2 各外设 DMA 配置

| 外设 | DMA 模式 | 缓冲区 | 方向 | 触发 | 优先级 |
|------|----------|--------|------|------|--------|
| ADC1 | Circular | 64 × uint16 | 外设→内存 | ADC EOC | 高 |
| USART1_RX | Circular | 128 bytes | 外设→内存 | USART IDLE | 高 |
| USART1_TX | Normal | 按帧分配 | 内存→外设 | TXE | 中 |
| SPI1_RX | Normal | 256 bytes | 外设→内存 | SPI RXNE | 中 |
| SPI1_TX | Normal | 256 bytes | 内存→外设 | SPI TXE | 中 |

> I2C1 (SHT20) 与 I2C2 (OLED) 单次数据量 ≤ 6 字节，使用中断模式即可，DMA 性价比不高，保留 DMA 通道给大数据量外设。

#### 4.9.3 ADC + DMA 循环采样模式

```c
#define ADC_DMA_BUF_SIZE 64
static uint16_t g_adc_dma_buf[ADC_DMA_BUF_SIZE];

void BSP_ADC_DMA_Start(void)
{
    HAL_ADC_Start_DMA(&hadc1,
                      (uint32_t *)g_adc_dma_buf,
                      ADC_DMA_BUF_SIZE);
}

void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    vTaskNotifyGiveFromISR(hSensorTaskHandle, &xHigherPriorityTaskWoken);
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    vTaskNotifyGiveFromISR(hSensorTaskHandle, &xHigherPriorityTaskWoken);
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

- 半满中断（32 次）+ 全满中断（64 次），每次触发后通知 `vSensorTask` 取数据
- 采样期间 **CPU 零介入**

#### 4.9.4 USART + DMA 收发模式

**DMA 环形接收 + IDLE 帧检测**：

```c
#define UART_RX_BUF_SIZE 128
static uint8_t g_uart_rx_buf[UART_RX_BUF_SIZE];

void BSP_UART_DMA_Start(void)
{
    __HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE);
    HAL_UART_Receive_DMA(&huart1, g_uart_rx_buf, UART_RX_BUF_SIZE);
}

void USART1_IRQHandler(void)
{
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE) != RESET)
    {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);
        HAL_UART_DMAStop(&huart1);

        uint16_t rx_len = UART_RX_BUF_SIZE -
                          __HAL_DMA_GET_COUNTER(huart1.hdmarx);
        /* 将 rx_len 字节数据推入消息队列，通知蓝牙任务 */
        xQueueSendFromISR(g_bt_rx_queue, g_uart_rx_buf, ...);

        HAL_UART_Receive_DMA(&huart1, g_uart_rx_buf, UART_RX_BUF_SIZE);
    }
}
```

- IDLE 中断识别帧尾，一次性处理完整帧
- 蓝牙任务从消息队列消费，不在高频中断中解析

**DMA 批量发送**：历史数据同步时连续发送多条记录，每次只需启动 DMA 即可返回，不阻塞任务。

#### 4.9.5 SPI + DMA Flash 读写

```c
void BSP_Flash_WritePage_DMA(uint32_t addr, uint8_t *buf, uint16_t len)
{
    BSP_W25Q64_WriteEnable();
    BSP_W25Q64_CS_Low();
    BSP_W25Q64_SendCmd(CMD_PAGE_PROGRAM);
    BSP_W25Q64_SendAddr(addr);
    HAL_SPI_Transmit_DMA(&hspi1, buf, len);
    /* 任务可继续执行其他逻辑 */
}

void HAL_SPI_TxCpltCallback(SPI_HandleTypeDef *hspi)
{
    if (hspi->Instance == SPI1)
    {
        BSP_W25Q64_CS_High();
        BSP_W25Q64_WaitBusy();
        xSemaphoreGiveFromISR(g_spi_dma_done, ...);
    }
}
```

- 写 256 字节扇区时，CPU 不再忙等 ~800µs，可同步处理其他逻辑

#### 4.9.6 FreeRTOS + DMA 联动模式

```
┌───────────────┐     DMA 传输完成      ┌──────────────────────┐
│  DMA 控制器    │ ──────────────────→  │  DMA 中断 ISR         │
│ (硬件搬运)     │                      │  → TaskNotifyFromISR  │
│ CPU 零介入     │                      │  → QueueSendFromISR   │
└───────────────┘                      └──────────┬───────────┘
                                                  │
                   ┌──────────────────────────────┘
                   ▼
         ┌────────────────────┐
         │  FreeRTOS 任务      │
         │  ulTaskNotifyTake  │  ← 等待 DMA 就绪通知
         │  或 xQueueReceive  │  ← 消费 DMA 填充的数据
         └────────────────────┘
```

#### 4.9.7 DMA 优化前后对比

| 指标 | 无 DMA | 有 DMA |
|------|--------|--------|
| ADC 中断频率 | 每次采样 1 次 | 每 64 次采样 1 次 |
| 蓝牙接收中断频率 | 每字节 1 次 | 每帧 1 次 (IDLE) |
| 蓝牙发送 100 条记录 CPU 占用 | ~80%（阻塞等待） | ~5%（启动即返回） |
| Flash 写 256 字节 CPU 状态 | 忙等 ~800µs | 同步执行其他任务 |
| vSensorTask 栈需求 | 256 words | 192 words (↓25%) |
| 系统 CPU 利用率 (估算) | ~60% | ~30% |

## 六、报警机制

| 报警条件 | 触发阈值 (默认) | 报警动作 |
|----------|----------------|----------|
| 温度过高 | > 40.0°C | 蜂鸣器急促响 + LED2 快闪 |
| 温度过低 | < 0.0°C | 蜂鸣器间隔响 + LED2 常亮 |
| 湿度过高 | > 85%RH | 蜂鸣器间隔响 + LED2 慢闪 |
| 湿度过低 | < 20%RH | 蜂鸣器间隔响 + LED2 慢闪 |
| 光照不足 | < 10% | LED2 闪烁 |
| 距离过近 | < 15cm | 蜂鸣器急促响 + LED2 快闪 |

> 所有阈值可通过菜单页面 2 实时修改，存入 Flash 永久保存。

## 七、蓝牙通信协议

### 7.1 主动上报帧 (MCU → 手机)

```
| STX  | DevID | 温度(f) | 湿度(f) | 光照(f) | 距离(f) | Alarm | XOR | ETX |
| 0xA5 | 0x01  | 4 bytes | 4 bytes | 4 bytes | 4 bytes | 1byte | 1B  |0x5A |
                                     总计 22 字节
```

### 7.2 指令下发帧 (手机 → MCU)

```
| STX  | DevID | CMD  | DATA(4B) | XOR | ETX |
| 0xA5 | 0x01  | 0x10 | TH_value | ... |0x5A |

CMD 定义:
  0x10: 设置温度上限
  0x11: 设置温度下限
  0x12: 设置湿度上限
  0x13: 设置湿度下限
  0x14: 设置光照下限
  0x15: 设置距离下限
  0x20: 查询当前数据 (DATA=0)
  0x30: 同步历史数据
```

## 八、RTOS 同步机制

| 资源 | 同步方式 | 说明 |
|------|----------|------|
| `g_stSensorData` | `osMutex` (互斥锁) | 传感器任务写，显示/存储/蓝牙读 |
| `g_stSysState` | `osMutex` (互斥锁) | 多任务读写保护 |
| 按键事件 | `osMessageQueue` | 输入任务 → 显示/分析任务 |
| 报警触发 | `osEventFlags` | 分析任务 → 报警任务 |
| 蓝牙数据发送 | `osMessageQueue` | 蓝牙任务消费 |
| 蓝牙数据接收 | `osMessageQueue` | DMA-IDLE ISR → 蓝牙任务 |
| 定时采集 | `osTimer` (软件定时器) | 精确采集间隔 |
| ADC-DMA 就绪 | `TaskNotify` | DMA 半满/全满 ISR → 传感器任务 |
| SPI-DMA 完成 | `BinarySemaphore` | DMA 完成 ISR → 存储任务 |

```
地址空间分配 (8MB = 0x000000 – 0x7FFFFF):

0x000000 ─┬─ Boot Sector (4KB)     : 系统配置、阈值参数
          ├─ Data Region (7.5MB)   : 循环存储传感器记录

          │   支持磨损均衡 (循环写入)
          │
0x7FF000 ─┴─ Reserved (4KB)        : 保留
```

## 十、后续升级路线：ESP32 + MQTT

### 10.1 升级目标

将通信方式从蓝牙透传升级为 **WiFi MQTT 物联网接入**，实现远程监控、云端存储、多设备联动。

### 10.2 两种升级方案

#### 方案 A：ESP32 协处理器模式 (推荐，改动最小)

```
STM32F103C8T6                ESP32-S3
┌──────────────┐    UART    ┌─────────────────┐
│ 传感器采集    │◄─────────►│ MQTT Client     │
│ OLED 显示    │  115200   │ WiFi STA/AP     │
│ Flash 存储   │           │ JSON 打包/解包   │
│ 报警管理     │           │ OTA 升级        │
│ 菜单交互     │           │ TLS 加密传输    │
└──────────────┘           └────────┬────────┘
                                    │
                              ┌─────▼─────┐
                              │  MQTT      │
                              │  Broker    │
                              └─────┬─────┘
                                    │
                         ┌──────────┼──────────┐
                         ▼          ▼          ▼
                      App/Web   InfluxDB   Grafana
```

- STM32 侧改动：将 USART1 从蓝牙改为 ESP32 通信
- ESP32 负责：WiFi 配网、MQTT 连接、JSON 序列化、TLS

#### 方案 B：ESP32 完全替代 STM32

- 所有传感器直接接入 ESP32-S3
- FreeRTOS 任务直接移植 (ESP-IDF 原生支持 FreeRTOS)
- 新增 MQTT 任务
- 适合新版本硬件迭代

## 十二、10 天开发计划与知识回顾

> 每天包含：**任务清单 → 验收标准 → 知识回顾 → 常见坑点提醒**

### 第 1 天：开发环境搭建 + 点灯

**任务清单**

1. 安装 ARM GCC 工具链 + VSCode + Cortex-Debug 插件
2. STM32CubeMX 新建工程：选型 STM32F103C8T6，配置 HSE + PLL → 72MHz
3. 配置 `PC13` 为 GPIO_Output（板载 LED），`PB3`、`PB4` 为输出
4. 生成代码，VSCode 中编译 → 烧录 → 验证 LED 闪烁
5. 用逻辑分析仪或示波器确认 SYSCLK = 72MHz

**验收标准**

```
□ LED1(PC13) 每 500ms 翻转一次 → 证明工具链/下载/时钟正常
□ 串口 printf 输出 "System Init OK, HCLK=72MHz"
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| STM32 时钟树 | HSI/HSE/PLL → SYSCLK → AHB/APB1/APB2 分频关系 |
| GPIO 八种模式 | 推挽/开漏、上下拉、输出速率选择 |
| 位带操作 | `PAout(n)` / `PBin(n)` 宏原理 |
| .ioc 文件结构 | CubeMX 生成代码的 MVC 层次：Core/Drivers/Middlewares |
| CMSIS 启动流程 | `startup_stm32f103xx.s` → `SystemInit()` → `main()` |

**常见坑点**

- CubeMX 默认可能不开启 SWD 调试口 → `SYS → Debug → Serial Wire`
- PC13 驱动能力弱，外部 LED 需加三极管或限流电阻 ≤ 2mA
- APB1 最大 36MHz，APB2 最大 72MHz，定时器时钟注意 ×1/×2 规则

### 第 2 天：FreeRTOS 入门 + 多任务点灯

**任务清单**

1. CubeMX 中启用 FreeRTOS（CMSIS_V2），配置 `configTICK_RATE_HZ = 1000`
2. 创建 `vLedTask_Run`：LED1 每 200ms 翻转，`vTaskDelay()` 实现
3. 创建 `vLedTask_Alarm`：LED2 每 1000ms 翻转

6. 在 `vTaskList()` 或调试器中观察三任务并发执行

**验收标准**

```
□ 3 个 LED 各自按不同周期独立闪烁 → 证明多任务调度正常
□ 任务名/状态/栈余量 能通过串口打印
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| FreeRTOS 内核启动 | `osKernelInitialize()` → `osKernelStart()` 流程 |
| 任务状态机 | Ready / Running / Blocked / Suspended 四态转换 |
| `vTaskDelay` vs `vTaskDelayUntil` | 相对延时 vs 绝对延时，周期抖动区别 |
| 任务优先级 | 0–(configMAX_PRIORITIES-1)，高数值=高优先级 |
| 栈溢出检测 | `configCHECK_FOR_STACK_OVERFLOW = 2`，钩子函数 |
| `FreeRTOSConfig.h` | `configTOTAL_HEAP_SIZE`、`configUSE_PREEMPTION` 等关键宏 |

**常见坑点**

- SysTick 被 FreeRTOS 接管，`HAL_Delay()` 可能失效 → 改用 `vTaskDelay()`
- 中断优先级：确保 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 设置正确（NVIC 优先级 4 位，值越小优先级越高）
- Heap 默认 `heap_4.c`，`configTOTAL_HEAP_SIZE` 先给 10KB（20KB SRAM 中剩余留给任务栈）

### 第 3 天：I2C 通信 + SHT20 温湿度传感器

**任务清单**

1. CubeMX 启用 I2C1（PB6/PB7），速率 100kHz（标准模式）
2. 编写 `bsp_sht20.c`：写命令 `0xF3`（温度）/ `0xF5`（湿度）

4. 温度/湿度计算公式实现（参考数据手册 §6.2）
5. 创建 `vSensorTask` 读取 SHT20，串口打印温度/湿度值
6. 对着自己哈一口气验证湿度变化

**验收标准**

```
□ 串口每 1s 输出：Temp=XX.X°C  Humi=XX.X%RH
□ 哈气后湿度值明显上升（验证传感器正常响应）
□ I2C CRC 校验通过（SHT20 自带 CRC）
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| I2C 协议 | Start/Stop/ACK/NACK 信号时序、7 位地址 + R/W 位 |
| I2C 时钟速率 | Standard(100k) / Fast(400k)，上拉电阻计算（一般 4.7kΩ） |
| SHT20 测量原理 | 电容式湿度 + 带隙温度，14 位 ADC 转换 |
| HAL_I2C API 选型 | `Master_Transmit/Receive`（阻塞）vs `_IT`（中断）vs `_DMA` |
| C 语言浮点数 | IEEE 754 格式，`float` 精度 6–7 位有效数字，`sprintf` 格式化 |

**常见坑点**

- SHT20 地址 0x40（7 位），HAL 库会自动左移，CubeMX 填入 `0x40 << 1`
- 测量后需要等待（温度 ~85ms，湿度 ~29ms），不可立即读取
- I2C 上拉电阻必须接，否则波形畸变导致通信失败
- SHT20 在 1.8–3.6V 供电，STM32 PA 耐 5V 但 PB 不耐 5V，注意电平匹配

### 第 5 天：ADC + DMA + 光敏电阻

**任务清单**

1. CubeMX 启用 ADC1 → Channel 2 (PA2)，12 位分辨率
2. CubeMX 添加 DMA1_CH1，Circular 模式，目标数组 64 × uint16
3. 编写 `bsp_light.c`：ADC-DMA 初始化 + 启动
4. HAL 回调中通过 `vTaskNotifyGiveFromISR` 通知 `vSensorTask`
5. `vSensorTask` 中 `ulTaskNotifyTake` 等待 DMA 就绪 → 滑动均值滤波
6. OLED 上添加光照显示（百分比）
7. 用手遮挡 / 手电筒照射光敏电阻，观察值变化

**验收标准**

```
□ OLED 显示：Light=XX% ，遮挡后数值明显下降
□ DMA 半满/全满中断正常触发（各 32 次/批）
□ ADC 原始值范围：全暗 ≈ 0–200，全亮 ≈ 3800–4095
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| ADC 分辨率 | 12 位 = 4096 级，参考电压 3.3V → 每级 0.806mV |
| ADC 采样时间 | `SamplingTime` = (采样周期数) × (1/ADCCLK)，ADCCLK ≤ 14MHz |
| DMA 控制器 | 7 通道，Circular vs Normal 模式区别 |
| DMA 中断 | 半满中断（HT）、全满中断（TC）、错误中断（TE） |
| FreeRTOS 任务通知 | `TaskNotify` 比信号量快 ~45%，无需创建内核对象 |
| 滑动均值滤波 | `sum += new - old; avg = sum / N`，O(1) 复杂度 |

**常见坑点**

- ADC Clock 不得超过 14MHz，APB2 72MHz → 预分频至少 ÷6
- DMA Circular 模式下数据不断覆盖，需在半满/全满中断中及时取走
- 光敏电阻是模拟量，引脚附近 PCB 走线尽量短、远离高频信号
- `HAL_ADC_Start_DMA` 在 FreeRTOS 启动后才能调用，不可在 `main()` 的 `osKernelStart()` 之前

### 第 6 天：定时器输入捕获 + HC-SR04 超声波测距

**任务清单**

1. CubeMX 配置 TIM2 → CH1 输入捕获模式（PA1 = Echo）
2. PA0 设为 GPIO_Output（Trig），初始低电平
3. 编写 `bsp_hcsr04.c`：
   - `HCSR04_Trig()` → PA0 输出 ≥10µs 高脉冲
   - 输入捕获中断中计算高电平时间 → `距离 = 时间/58`
4. 创建 `HCSR04_Read()` API，返回 `float` 距离值
5. `vSensorTask` 中调用，OLED 显示距离值
6. 在 10cm / 50cm / 100cm / 200cm 处验证测量精度

**验收标准**

```
□ OLED 显示：Dist=XX cm，精度 ±1cm（2m 以内）
□ 不同距离实测对照卷尺，误差 < 3%
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| 定时器时基 | PSC（预分频器）+ ARR（自动重装载）→ 定时频率/周期 |
| 输入捕获原理 | 检测边沿 → 锁存 CNT 到 CCRx → 两次边沿差值 = 高电平时间 |
| 声速公式 | v = 331.4 + 0.607×T（m/s），T 为摄氏温度 |
| 定时器中断优先级 | IC 中断 > 溢出中断，确保捕获不被遗漏 |
| NVIC 优先级分组 | PreemptionPriority + SubPriority 分配 |

**常见坑点**

- Trig 脉冲必须 ≥ 10µs，`delay_us(15)` 更安全
- 超声波模块要求 5V 供电，但 Echo 输出 5V → **必须分压到 3.3V**，否则烧 PA1
- TIM2 挂在 APB1（36MHz），若 APB1 预分频 ≠ 1，定时器时钟 = APB1×2 = 72MHz
- 输入捕获前先清 SR 标志位，否则可能读到旧值
- 可用 SHT20 温度做声速补偿（Day 3 的数据联用）：`dist_cm = time_us * (331.4 + 0.607 * temp) / 20000`

---

### 第 7 天：旋转编码器 + 按键 + 菜单系统

**任务清单**

1. CubeMX 配置 PB0/PB1 为 GPIO_EXTI（双边沿中断），PB12/PB13/PB14 为 GPIO_EXTI（下降沿）
2. 编写 `bsp_encoder.c`：
   - A/B 相状态机解码（查表法，4× 分辨率）→ 输出 `Encoder_Dir_t` + 步进计数
3. 编写 `app_menu.c`：4 页面菜单状态机
   - 页面 0：主界面（温湿度/光照/距离）
   - 页面 1：数据详情
   - 页面 2：阈值设置（选中项闪烁）
   - 页面 3：系统信息
4. 创建 `vInputTask`：50ms 周期扫描按键 + 编码器消息入队
5. 按键消抖：连续 3 次读到同一状态才确认（15ms 确认周期）
6. 旋转编码器 KEY 脚：区分单击（切换页面）/ 长按（确认）/ 双击（返回）

**验收标准**

```
□ 旋转编码器正转/反转：菜单选项上下滚动
□ KEY1 单击：切换页面；KEY1 长按：进入编辑模式
□ 阈值编辑模式下，编码器修改数值，OLED 实时刷新
□ 按键无抖动误触
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| 正交编码原理 | A/B 相 90° 相位差，正反转状态转移图 |
| EXTI 外部中断 | 16 条中断线（EXTI0–15），双边沿 / 上升沿 / 下降沿 |
| 按键消抖 | 硬件（RC 滤波）vs 软件（多次采样 / 定时器消抖） |
| 状态机设计 | 菜单状态机：BROWSE → EDIT → CONFIRM 三态 |
| `osMessageQueue` | CMSIS_V2 消息队列，支持 ISR 中 `xQueueSendFromISR` |
| C 语言 `enum` | 页面枚举 `PAGE_MAIN / PAGE_DETAIL / PAGE_THRESHOLD / PAGE_INFO` |
| C 语言 `union` | 按键事件 `typedef union { struct { uint8_t src:4, type:4; }; uint8_t raw; } KeyEvent_t;` |

**常见坑点**

- EC11 编码器机械抖动严重，A/B 相中断必须加简单的去抖（如 1ms 内重复中断忽略）
- PB0/PB1 同时开 EXTI 占两条中断线，中断函数中要判断是哪个引脚触发
- 菜单编辑模式下的数值修改要立即写入 `g_stSysState`，并及时刷新 OLED
- 编码器旋转一圈 20 脉冲，4× 解码后 80 步，步进值可调（×1/×5/×10）

### 第 8 天：FreeRTOS 多任务集成 + 同步机制

**任务清单**

1. 合并前 7 天代码：8 个 FreeRTOS 任务全部创建
2. `vSensorTask`：整合 SHT20 + HC-SR04 + ADC-DMA 三个传感器，统一 1s 周期
3. `vAnalysisTask`：读取 `g_stSensorData` → 与 `g_stSysState` 阈值比较 → 设置事件标志
4. 互斥锁保护：`osMutexNew` 保护 `g_stSensorData` 和 `g_stSysState`
5. 消息队列：按键事件（KeyEvent_t）入队 → `vDisplayTask` 消费
6. 事件标志：`osEventFlagsNew` 用于分析任务 → 报警任务通知
7. 调优任务栈：`uxTaskGetStackHighWaterMark()` 检查各任务栈余量

**验收标准**

```
□ 8 个任务全部正常运行，串口打印任务列表 + 栈水位
□ 互斥锁无死锁，消息队列无溢出
□ CPU 空闲率 > 50%（vTaskList 中 IDLE 任务）
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| 互斥锁 vs 信号量 | Mutex 有优先级继承，Semaphore 无 |
| 消息队列阻塞 | `osMessageQueuePut/Get` 的 timeout 参数：0/不阻塞/永久 |
| 事件标志位 | 32 位标志，`osFlagsWaitAll` vs `osFlagsWaitAny` |
| 死锁条件 | 互斥/持有等待/不可剥夺/循环等待 → 破坏其一即可避免 |
| 栈水位监测 | `uxTaskGetStackHighWaterMark(NULL)` 返回剩余栈空间（words） |
| 优先级翻转 | 经典例子：火星探路者，解决方法：优先级继承 |

**常见坑点**

- Mutex 在 `osKernelStart()` 之前创建，否则返回 NULL
- 不要在 ISR 中调用 `osMutexAcquire`（无 `FromISR` 版本）→ ISR 中只能用 `TaskNotify` 或 `Semaphore`
- 消息队列大小计算：`osMessageQueueNew(msg_count, msg_size, ...)` 的 `msg_size` = `sizeof(KeyEvent_t)` 而非指针大小
- 互斥锁持有时间尽量短（只保护赋值操作），不要锁住整个 OLED 刷新函数

### 第 9 天：蜂鸣器报警 + W25Q64 Flash 存储

**任务清单**

1. 蜂鸣器：
   - TIM1_CH1（PA8）PWM 输出，频率 2kHz，占空比 50%
   - `vAlarmTask` 响应事件标志：急促鸣 / 间隔鸣 / 关闭
2. W25Q64 Flash：
   - CubeMX 启用 SPI1（PA5/PA6/PA7），PA4 作 CS
   - 编写 `bsp_w25q64.c`：读 ID、写使能、扇区擦除（0x20）、页写入（0x02）、读取（0x03）
   - 阈值参数存入 0x000000 扇区：上电读取 → 恢复用户设置
3. `vStorageTask`：每分钟将 `SensorData_t` 写入 Flash（SPI-DMA，信号量同步）
4. 验证 Flash 存储：写入 → 断电 → 重新上电 → 读取确认数据正确

**验收标准**

```
□ 温度超过 40°C → 蜂鸣器急促响 + LED2 快闪
□ 阈值修改后断电再上电 → 阈值保持（Flash 恢复成功）
□ W25Q64 ID 读取 = 0xEF4017（确认通信正常）
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| PWM 原理 | ARR 定周期、CCR 定占空比，`Duty = CCR / ARR × 100%` |
| SPI 协议 | CPOL/CPHA 四种模式，Mode 0/3 常见，W25Q64 = Mode 0/3 |
| Flash 存储结构 | Page(256B) → Sector(4KB) → Block(64KB)，写前必擦 |
| Flash 写入寿命 | W25Q64 典型 10 万次擦写/扇区，磨损均衡策略 |
| `memcpy` 与指针 | `SensorData_t` 序列化为 `uint8_t[20]` 写入 Flash |
| SPI DMA 同步 | `HAL_SPI_TxCpltCallback` → `xSemaphoreGiveFromISR` |

**常见坑点**

- SPI 片选 CS 必须软件控制（GPIO），不能依赖硬件 NSS
- Flash 写入前必须发写使能命令（0x06），写完自动失能
- 扇区擦除耗时 ~45ms，页写入 ~3ms，期间芯片忙（读状态寄存器 SR BIT0）
- PWM 频率 `Fpwm = TimerCLK / ((PSC+1) × (ARR+1))`，蜂鸣器推荐 2–4kHz
- 阈值初始化：首次上电 Flash 全 0xFF → 检测到 FF 则写入默认阈值

### 第 10 天：蓝牙通信 + 系统集成联调

**任务清单**

1. HC-05 蓝牙：
   - CubeMX 启用 USART1（PA9/PA10），波特率 9600
   - 编写 `bsp_bt.c`：AT 指令配置（设备名/配对码/主从模式）
   - 实现 DMA 环形接收 + IDLE 帧检测 → 消息队列 → `vBluetoothTask`
2. 编写 `app_protocol.c`：
   - 帧打包：`protocol_pack()` → 20 字节主动上报帧
   - 帧解包：`protocol_unpack()` → 解析手机端指令（设置阈值等）
   - XOR 校验：`protocol_calc_xor()` → 验证/生成校验字节
3. 手机端验证：
   - 安卓：下载"蓝牙串口"App，连接 HC-05
   - 接收数据帧，十六进制查看，验证格式正确
   - 发送指令帧修改温度阈值 → OLED 上确认阈值已变更
4. 全系统联调：
   - 上电运行 10 分钟，观察各任务稳定运行
   - 温湿度/光照/距离 → OLED 正常刷新 → 蓝牙正常上报
   - 超阈值触发报警 → 蜂鸣器 + LED 正常响应

**验收标准**

```
□ 手机蓝牙串口正确接收 22 字节上报帧（频率 = 1Hz）
□ 手机发送 0xA5 01 10 00 00 20 41 XX 5A → 温度上限设为 10.0°C（float=0x41200000）
□ 10 分钟连续运行：无任务阻塞、无栈溢出、无内存泄漏
□ Flash 存储 → 蓝牙同步读取历史数据指令（CMD=0x30）
```

**知识回顾**

| 知识点 | 回顾内容 |
|--------|----------|
| UART 协议 | 起始位/数据位/校验位/停止位，波特率误差容忍度 ±2% |
| DMA IDLE 中断 | UART 总线空闲 ≥1 字节时间 → 触发 IDLE 中断 → 帧尾识别 |
| 自定义二进制协议 | STX/ETX 帧定界、XOR 校验、命令码 + 数据字段 |
| 蓝牙 AT 指令 | `AT+NAME=xxx`、`AT+PSWD=1234`、`AT+ROLE=0` |
| 大小端序 | STM32 小端，蓝牙传输统一大端 → `htonl()`/`ntohl()` |
| 内存对齐 | `__attribute__((packed))` 或 `#pragma pack(1)` 对齐结构体 |

**常见坑点**

- HC-05 上电默认 9600，进入 AT 模式需按住 KEY 再上电（或拉高 EN 引脚）
- USART1 的 TX(PA9)/RX(PA10) 也可能用于下载，注意和 USB-TTL 冲突
- DMA IDLE 中断后必须 `__HAL_UART_CLEAR_IDLEFLAG(&huart1)`，否则死循环
- 帧校验 XOR = 所有数据字节异或，发送端算一遍、接收端比对
- `float` 在 STM32 和手机端（Java/JS）的 IEEE 754 一致，但 `double` 需注意 4 字节 vs 8 字节

## 十三、风险与注意事项

1. **I2C 总线冲突**：SHT20 (I2C1) 与 OLED (I2C2) 使用不同 I2C 外设，互不干扰
2. **HC-SR04 精度**：受温度影响，后续可用 SHT20 温度值做声速补偿
3. **W25Q64 写入寿命**：10 万次擦写/扇区，循环写入策略可有效延长寿命
4. **FreeRTOS 堆栈**：STM32F103C8T6 仅 20KB SRAM，需严格控制任务栈大小
5. **蓝牙升级平滑过渡**：保留 USART1 作为通信接口，后续从 HC-05 切换到 ESP32 时只需修改通信协议层
